# 1. I2C 기초와 센서 레지스터 읽기

## 1.1 핵심 개념

I2C는 `SDA` 데이터와 `SCL` 클럭을 여러 장치가 공유하는 주소 기반 버스다. 컨트롤러가 START, 7비트 주소와 R/W 비트, ACK/NACK, STOP을 만든다. 많은 센서는 “레지스터 주소 쓰기 → repeated START → 데이터 읽기” 순서를 사용한다.

```text
3.3V ─┬─ pull-up ─ SDA ─┬─ Jetson controller
      └─ pull-up ─ SCL ─┤
                        ├─ sensor 0x40
                        └─ EEPROM 0x50
GND  ───────────────────── common
```

주소 표기가 `0x76`인지, R/W 비트를 포함한 8비트 값 `0xEC/0xED`인지 데이터시트에서 확인한다. Linux에는 보통 **7비트 주소**를 전달한다.

## 1.2 배선

대표 실습은 J12 I2C #1을 쓴다.

| J12 | Jetson 신호 | 센서 |
|---:|---|---|
| 1 또는 17 | 3.3V | VCC(3.3V 호환일 때만) |
| 3 | I2C1_SDA | SDA |
| 5 | I2C1_SCL | SCL |
| 6 등 | GND | GND |

전원을 끄고 배선한다. 센서 보드의 내장 pull-up과 전압을 확인한다. 5V로 pull-up된 모듈은 직접 연결하지 않는다.

## 1.3 장치 찾기

J12의 I2C #1이 항상 `/dev/i2c-1`이라는 보장은 없다.

```bash
i2cdetect -l
ls -l /dev/i2c-*
sudo i2cdetect -y -r <확인한_bus_number>
```

`UU`는 커널 드라이버가 주소를 점유했다는 뜻이다. 해당 드라이버를 무작정 해제하지 않는다. `i2cdetect`도 일부 장치에 부작용이 있으므로 주소를 알고 있으면 전체 스캔보다 지정 주소 접근을 우선한다.

## 1.4 C++ 실습

예제는 8비트 레지스터 주소를 쓰고 repeated START로 1~256바이트를 읽는다.

```bash
./build/bin/i2c_read /dev/i2c-7 0x76 0xD0 1
```

센서 데이터시트의 chip-ID 레지스터처럼 읽기만 해도 안전한 레지스터를 선택한다. 16비트 레지스터 주소, SMBus PEC, block command가 필요한 장치는 예제를 확장해야 한다.

## 1.5 실무 확인

- `ENXIO/Remote I/O error`: 주소 NACK, 전원·GND·주소·SDA/SCL 뒤바뀜을 확인한다.
- 버스가 계속 Low: 전원을 끄고 장치를 하나씩 분리한다. 잘못된 전압, 멈춘 장치, 너무 강한 pull-up을 확인한다.
- 간헐 오류: 속도를 낮추고 케이블을 줄이며 오실로스코프로 rise time과 ringing을 본다.
- Vision 시스템에서는 카메라 제어 I2C와 외부 센서 I2C를 혼동하지 않고 device-tree mux 경로까지 기록한다.
