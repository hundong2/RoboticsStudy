# 7. 문제 해결과 실습 완료 기준

## 7.1 순서대로 확인하기

1. 전원을 끄고 부품 전압, 핀 번호, GND, 방향을 육안·연속성 모드로 확인한다.
2. 주변 장치를 분리한 상태에서 Jetson이 정상 부팅되는지 본다.
3. `/etc/nv_tegra_release`, model, 활성 DTB/overlay를 기록한다.
4. Jetson-IO에서 pinmux를 확인하고 변경했다면 재부팅한다.
5. 장치 노드와 소유권을 확인한다.
6. 저속·짧은 payload·읽기 전용 동작부터 시작한다.
7. kernel log와 subsystem 통계를 확인한다.
8. 멀티미터, 로직 애널라이저, 오실로스코프로 전압과 파형을 확인한다.

## 7.2 공통 명령

```bash
sudo dmesg --follow
journalctl -k -b
sudo /opt/nvidia/jetson-io/config-by-pin.py
ls -l /dev/i2c-* /dev/ttyTHS* /dev/spidev* /dev/gpiochip* 2>/dev/null
```

`Permission denied`를 `chmod 777`로 영구 해결하지 않는다. 실제 service account를 `dialout`, `i2c`, `gpio` 등 배포판의 적절한 그룹에 넣거나 최소 권한 udev rule을 작성한다.

## 7.3 실습별 합격 기준

| 실습 | 합격 조건 | 추가 계측 |
|---|---|---|
| I2C | 알려진 read-only register 값 일치, 반복 100회 오류 없음 | SDA/SCL idle High와 rise time |
| UART | 3개 baud rate에서 payload byte-for-byte 일치 | TX bit time 확인 |
| SPI | 0.5/1/5 MHz loopback 일치 | mode와 SCK/MOSI/MISO 파형 |
| GPIO | 지정 line만 토글, 재부팅 중 안전 상태 유지 | High/Low 전압과 glitch |
| PWM | 주파수·duty 오차 허용범위 만족, 종료 후 disable | scope 측정 |
| CAN | 양방향 frame, error counter 0, bus-off 복구 검증 | 종단 60 ohm, dominant 전압 |

## 7.4 코드 적용 전 체크리스트

- [ ] 물리 핀, Linux 장치, GPIO offset을 현재 보드에서 확인했다.
- [ ] 전압과 pull-up 전원을 확인했다.
- [ ] output conflict가 없고 부하 driver를 사용했다.
- [ ] 실패 timeout과 signal 종료 처리가 있다.
- [ ] 프로세스가 종료되면 PWM/enable/actuator가 안전 상태가 된다.
- [ ] 입력 frame에 길이·범위·CRC·timestamp 검증이 있다.
- [ ] kernel driver가 있는 장치를 userspace bit-banging으로 재구현하지 않았다.
- [ ] BSP/DT 변경 후 이 실습을 자동 회귀 시험으로 다시 실행한다.
