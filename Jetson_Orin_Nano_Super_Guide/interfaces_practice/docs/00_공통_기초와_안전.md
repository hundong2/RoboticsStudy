# 0. 공통 기초와 안전

## 0.1 핀 표에서 읽어야 하는 것

핀 설명은 단순한 이름표가 아니다. 다음 항목을 함께 읽는다.

- **전압 영역**: 1.8V, 3.3V, 5V 중 무엇인지 확인한다. J12 신호는 3.3V지만 CSI의 일부 제어 신호는 1.8V다.
- **방향**: `Input`, `Output`, `Bidir`는 Jetson 기준이다. `UART_TX`는 Jetson이 내보내므로 상대 장치 RX에 연결한다.
- **active-low**: 이름 뒤 `*`, `#`, `_N`이 있으면 낮은 전압이 활성 상태다.
- **pull-up/down**: 입력이 뜨지 않도록 약한 기본 상태를 만든다. I2C는 open-drain이므로 pull-up이 통신의 일부다.
- **GPIO/SFIO**: 같은 pad가 범용 GPIO 또는 I2C·SPI·UART 같은 전용 기능(SFIO) 중 하나로 mux된다.
- **물리 핀과 Linux 이름**: J12 물리 핀 15가 곧 GPIO line 15라는 뜻이 아니다.

## 0.2 전압, 전류, 임피던스

디지털 입력은 전압을 읽고, 출력은 논리 상태를 만든다. GPIO의 3.3V 표시는 “3.3V 부하 전원”이 아니라 논리 전압이다. 출력에 큰 전류를 요구하면 전압이 무너지고 SoC·레벨 변환기가 손상될 수 있다.

```text
Jetson GPIO ── 1k~10k ──> MOSFET/드라이버 ──> 모터·릴레이·LED 부하
      GND ────────────────────────────────> 공통 GND
```

로직 애널라이저도 입력 허용 전압을 확인한다. 일반 오실로스코프의 접지 클립은 보호 접지에 연결될 수 있으므로, 접지 기준이 다른 전원 회로에 무심코 물리지 않는다.

## 0.3 push-pull과 open-drain

- push-pull 출력은 High와 Low를 모두 능동적으로 구동한다. UART, SPI clock/data가 대표적이다.
- open-drain 출력은 Low만 구동하고 High는 pull-up 저항이 만든다. I2C SDA/SCL이 대표적이다.
- 두 push-pull 출력을 서로 연결하면 한쪽 High와 다른 쪽 Low가 충돌할 수 있다.
- I2C pull-up을 여러 모듈이 각각 가지고 있으면 병렬 합성 저항이 너무 작아져 sink current가 커질 수 있다.

## 0.4 공통 접지와 배선 품질

신호는 전압의 차이이므로 두 장치의 GND를 연결해야 한다. 짧은 저속 실습부터 시작하고, 속도가 올라가면 GND 귀환 경로·케이블 길이·종단·레벨 시프터의 대역폭을 고려한다.

```text
Jetson signal ───────────────── sensor signal
Jetson GND    ───────────────── sensor GND
Jetson 3.3V   ──(필요 전류 검토)── sensor VCC
```

센서를 별도 전원으로 공급해도 GND는 공통으로 연결한다. 단, 절연형 인터페이스는 절연 경계를 설계에 따라 유지한다.

## 0.5 핀 기능과 장치 노드 확인

```bash
# 보드·릴리스
cat /etc/nv_tegra_release
cat /proc/device-tree/model; echo

# Jetson-IO가 인식한 헤더와 기능
sudo /opt/nvidia/jetson-io/config-by-pin.py
sudo /opt/nvidia/jetson-io/config-by-function.py -l enabled

# Linux 장치
ls -l /dev/i2c-* /dev/ttyTHS* /dev/spidev* /dev/gpiochip* 2>/dev/null
i2cdetect -l
gpioinfo
ip -details link show type can
ls -l /sys/class/pwm 2>/dev/null
```

SPI·I2S·PWM 등의 SFIO를 바꿨다면 Jetson-IO에서 저장하고 재부팅한다. 제품 BSP에서는 Jetson-IO를 현장 설정 도구로 의존하기보다 검증된 pinmux/DTB를 빌드·플래시 산출물로 관리한다.

## 0.6 실험 기록 양식

각 실습 때 다음을 기록하면 BSP 변경 후 회귀 시험에 그대로 쓸 수 있다.

| 항목 | 예시 |
|---|---|
| 보드/SOM | P3768-0000 / P3767-0005 |
| Jetson Linux | `/etc/nv_tegra_release` 전체 |
| DTB/overlay | 활성 boot entry와 DTBO |
| 물리 핀 | J12 pin 3, 5, 6 |
| Linux 장치 | `/dev/i2c-7`처럼 실제 확인값 |
| 주변 장치 | 부품명, 전압, 주소, 데이터시트 revision |
| 계측 | idle 전압, clock 속도, 파형 캡처 |
| 판정 | 명령, 예상값, 실제값, 오류 로그 |
